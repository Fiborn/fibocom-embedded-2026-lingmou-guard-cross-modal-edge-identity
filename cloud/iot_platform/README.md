# 物联网平台后端

设备接入与服务端业务逻辑，包括 WebSocket 通信、识别结果转发和设备状态管理。

## 当前内容

- `websocket1v4.py`：WebSocket 服务实现。
- `start.sh`：服务启动脚本。

## 服务职责与数据

`websocket1v4.py` 用于维护边缘设备与客户端间的实时消息通道。消息应按用途区分为认证、状态、识别事件、训练/管理请求和心跳；所有客户端输入均需做身份校验、字段校验和频率控制。

`start.sh` 会尝试启动 SRS 容器和 WebSocket 服务。脚本中端口映射目前未配置完整，部署前必须补全端口、网络策略、镜像来源和运行账号；不要在脚本内固化真实 IP、令牌或密码。

## 运维检查清单

- 以非 root 账号运行应用与容器。
- 启用 TLS，限制管理端来源，并配置连接数/消息大小上限。
- 对事件日志做字段脱敏和保留期限控制。
- 为进程、容器和磁盘空间设置健康检查与告警。

## 启动与验证步骤

在 Linux 服务器上准备 Python、Docker 和网络访问条件后，先审查 `start.sh` 中的镜像、端口映射和候选地址配置。仅在确认端口由防火墙、反向代理和 TLS 策略保护后，才执行启动脚本；脚本会管理 SRS 容器并启动 `websocket1v4.py`。首次运行应使用测试令牌和模拟消息，不要直接连接真实摄像头或人脸库。

验证时可依次检查：服务进程是否存活；WebSocket 是否能建立认证后的连接；心跳是否按预期返回；非法令牌、超大消息和异常 JSON 是否被拒绝；重启服务后客户端是否能退避重连。查看日志时，不应记录令牌、完整认证报文、原始人脸图像或特征向量。若需要排查连接失败，可记录时间、请求类型、设备匿名标识和错误码。生产发布前还应配置日志轮转、容器自动恢复、备份策略和升级回滚方案。
