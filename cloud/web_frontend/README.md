# 可视化前端

本目录包含监控、告警、设备管理和人脸库管理相关的前端工程。

## 当前内容

- `APP/`：移动端应用工程。
- `HTML/`：浏览器端页面与静态资源。

`APP/package.json` 表明该工程采用 uni-app 多页面组织，并使用 `easyplayer` 与 `echarts` 处理视频展示和数据可视化；`APP/manifest.json` 用于管理应用平台配置。

## 本地开发建议

1. 使用与团队一致的 Node.js 版本安装依赖。
2. 在 `APP/` 中通过 uni-app/HBuilderX 或项目既定构建工具运行调试。
3. 将服务地址放入未提交的环境配置，不写入组件、页面或构建产物。
4. 用脱敏的模拟事件验证告警列表、播放页面和人脸库管理界面。

## 发布前检查

- 不发布 `node_modules/`、`unpackage/`、缓存和含真实数据的截图。
- 检查视频播放器鉴权、跨域策略和 WebSocket 重连逻辑。
- 关闭调试日志、示例账户和测试接口。

## 页面使用说明

前端主要承载实时监控、事件告警、设备状态与人脸库管理等交互。开发时先在 `APP/` 目录安装依赖，并使用 uni-app/HBuilderX 打开工程；浏览器端页面和静态资源位于 `HTML/`。启动后应先进入模拟或测试环境，确认播放器可以处理断流、加载失败和重复连接，再连接受保护的后端服务。任何接口地址、认证方式和环境开关都应通过未提交的配置注入。

页面设计应遵循最小展示原则：实时画面默认不展示真实姓名和完整特征信息；事件列表只显示必要的匿名标识、状态和时间；管理员操作应有确认提示和审计记录。测试人脸库上传、删除或训练任务时，使用授权的脱敏样本，并验证取消、超时和失败提示是否清晰。构建发布包前，清理 `node_modules`、`unpackage`、截图、开发日志和本地配置，使用干净浏览器或移动设备回归验证登录、播放、告警和网络恢复行为。
