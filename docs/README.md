# 项目文档

本目录存放设计报告、部署手册、测试记录和对外展示材料。当前包含 `灵眸卫士_技术文档.pdf`，其中记录系统方案、性能指标与参考文献。

## 文档体系

| 文档 | 应覆盖的内容 |
| --- | --- |
| 系统架构 | 端、边、云模块边界、数据流和异常路径 |
| 硬件部署 | 接线、供电、镜头、云台和安装说明 |
| 算法模型 | 模型来源、输入输出、评测条件和局限性 |
| 部署运维 | 环境、启动顺序、日志、监控和排障 |
| 测试报告 | 测试场景、样本范围、指标、结论和复现步骤 |

## 发布前检查

1. 核对图表、模型名称、硬件版本与代码版本一致。
2. 移除真实人脸、人员名称、账号、设备地址和告警截图。
3. 清除 PDF/DOCX 的作者、修订者、批注、隐藏文本和文件路径元数据。
4. 对性能结论注明测试条件、样本范围和可复现步骤。

新增文档优先使用 Markdown，并从根目录 README 建立链接。

## 使用方法

阅读技术报告时，建议先从项目根目录 README 了解整体目标，再依次查看本目录中的系统设计、硬件、算法和测试材料。需要复现实验时，应先记录报告对应的代码提交、模型版本、设备型号、镜头焦距、光照条件和测试距离；仅凭最终准确率不能判断不同版本是否可比。新增部署文档时，采用“前置条件—配置步骤—启动命令—验证结果—故障处理”的结构，命令中的地址、账号和令牌使用占位符表示。

若文档需要包含界面截图，请优先使用模拟数据和已授权样本。必须展示识别流程时，应遮挡人脸、姓名、特征库标签、设备编号、时间戳和网络地址；并在图注中说明截图经过脱敏。发布 PDF 前，除检查正文外，还应在办公软件的“检查文档”功能中清除批注、修订记录与自定义属性，再重新导出并抽查文件元数据。这样可以使技术资料既能支持评审、交接与维护，也不会将运行环境或个人数据带出项目边界。
