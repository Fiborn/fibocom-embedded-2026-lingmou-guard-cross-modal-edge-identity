# 业务算法

放置直接服务于设备业务的算法工程，包括人脸检测、识别、跟踪、云台控制和视频流处理。

## 当前模块

- `AeroFace Edge/`：边缘端人脸识别、跟踪与告警服务。

## 算法处理链

`AeroFace Edge` 将视频帧经 SCRFD 人脸检测、ByteTrack/IoU 跟踪、AdaFace 特征提取与本地特征库比对后，输出人脸框、跟踪 ID、身份状态和事件信息；可选地将目标位置发送给舵机控制器，并以 WebSocket/视频流形式上报。

## 模块准入要求

- 新算法必须说明模型许可证、硬件要求、输入尺寸、输出字段和性能基准。
- 模块启动不得依赖工作目录；路径应从模块配置或项目根目录解析。
- 对外上报只发送业务所需字段，默认不发送原始帧、人脸裁剪图或特征向量。

## 使用方法

算法模块应在自己的目录内启动，并使用模块 README 指定的环境变量和模型路径。以 `AeroFace Edge` 为例，启动前先配置摄像头、识别模型、特征库目录和可选云台串口；之后先执行离线摄像头测试，确认可以持续读取图像，再启用识别、事件上报和推流。建议将检测、跟踪、识别和上报分阶段打开，这样可以快速判断故障位于图像采集、模型推理、特征库还是网络通信。

日常维护时，使用脱敏视频或授权测试样本验证以下结果：检测框应覆盖人脸；同一目标的跟踪 ID 在连续帧中稳定；低质量或遮挡目标不会被错误确认；新增或删除特征后无需重启即可生效；网络恢复后不会重复发送大量过期事件。算法参数变更应记录阈值、模型版本、场景和评测结果。若要新增算法工程，应先建立独立 README、配置模板、最小测试数据说明和回归脚本，再接入主业务链。
