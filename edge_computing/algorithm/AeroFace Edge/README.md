# AeroFace Edge

AeroFace Edge 是运行在边缘设备上的人脸检测、跟踪、特征比对与事件上报服务。它面向摄像头输入，在本地完成主要识别链路，并可选联动云台与远程管理服务。

## 目录结构

```text
├─ app/                 # 配置与运行时编排
├─ models/              # SCRFD 与 AdaFace 推理模型
├─ tools/               # 检测、识别、融合与跟踪适配工具
├─ tracker/             # ByteTrack 及卡尔曼滤波相关实现
├─ facedata/            # 历史运行数据目录；不得提交真实数据
├─ main.py              # 兼容启动入口
├─ _legacy_engine.py    # 现有业务引擎实现
└─ servo.py             # 云台/舵机联动逻辑
```

## 启动前准备

1. 使用目标设备已验证的 Python、OpenCV、AIDLite、NumPy 与 WebSocket 运行环境。
2. 确认 `models/` 中的人脸检测与识别模型完整且与代码版本匹配。
3. 参考 `.env.example` 在设备的受保护环境中设置服务器、端口、令牌、推流与数据路径。
4. 核对摄像头设备号、分辨率、帧率、舵机串口和供电状态。

## 安全边界

- `.env`、`facedata/`、`data/`、日志和抓拍图不应提交。
- 人脸特征库与训练图像仅可在获得授权的设备和存储空间内使用。
- 生产环境应使用加密传输、最小权限令牌和日志脱敏；不应通过未认证 WebSocket 传输原始人脸图像。

## 维护路线

现有引擎仍集中在 `_legacy_engine.py`。后续重构应优先将推流、相机采集、WebSocket 客户端、特征库和训练管理分别迁移到 `app/` 的独立模块，并在每次迁移后用脱敏视频做回归测试。

## 程序用法

进入本目录后，先依据 `.env.example` 在部署设备的安全配置中设置服务地址、端口、令牌、特征库路径和模型路径；不要复制真实配置到仓库。确认模型文件存在、摄像头可用、舵机串口可访问后，以 `python main.py` 启动服务。`main.py` 保持兼容入口职责，运行时由 `app/runtime.py` 组织启动流程，业务实现位于 `_legacy_engine.py`。首次启动建议关闭云台和推流，先在本地预览中确认摄像头帧、检测框和跟踪 ID 正常，再逐项打开识别、云台、事件上报和视频流。

训练或维护特征库时，只能使用获得授权的人脸样本。先用空特征库验证未知目标行为，再添加测试身份，检查识别结果、删除操作和热更新是否符合预期。运行中如果出现帧率下降，先检查摄像头分辨率、推理尺寸、模型加载状态、CPU/NPU 使用率和队列积压；如果网络事件延迟，检查 WebSocket 认证、服务可达性和上报冷却参数。停止程序时应先停止事件服务与推流，再释放摄像头和串口，避免下次启动出现设备被占用。模型或参数升级前保留可运行的上一版配置与模型，以便出现误识或性能回退时快速恢复。
