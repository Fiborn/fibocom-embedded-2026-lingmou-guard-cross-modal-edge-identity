# 边缘计算与智能算法

部署在边缘计算设备上，负责模型推理、目标跟踪、视频处理和设备侧算法服务。

## 目录说明

- `algorithm/`：面向业务的边缘算法与应用入口。
- `ai_model/`：训练代码、模型权重和模型转换相关资源。
- `requirements.txt`：Python 运行依赖清单。

## 运行边界

边缘端负责摄像头帧采集、检测、跟踪、特征提取、身份比对和本地控制；云端仅承担授权后的状态转发、远程管理和告警联动。这样可以缩短识别链路，也减少原始视频和生物特征数据离开设备的范围。

## 运行前检查

1. 在 SC171 设备的 AIDLite/Python 环境中确认摄像头、模型和硬件加速能力可用。
2. 为每个算法模块提供独立环境变量模板，不在代码中填写地址、令牌或推流地址。
3. 将模型、运行时数据和代码版本分别记录，便于排查性能差异。
4. `requirements.txt` 当前为空；部署前必须补齐并锁定实际验证过的依赖版本。

## 数据流

```text
摄像头 → 检测/跟踪 → 特征提取与本地比对 → 显示/云台控制 → 脱敏事件上报
```

## 设备侧使用步骤

将本目录部署到目标设备后，先确认 Python 版本与 AIDLite 运行时兼容，再按照算法模块的 `.env.example` 创建受保护的本地配置。检查模型文件是否存在、磁盘是否有足够空间、摄像头设备号是否正确，以及当前用户是否有访问摄像头和串口的权限。完成这些检查后启动算法入口，先用本地预览或脱敏测试视频确认检测框、跟踪 ID 与帧率正常，再连接云端事件服务和云台控制器。

上线时不要直接用真实人脸库做首次测试。应先使用空库或授权的测试样本，验证未知人员、已注册人员、网络断开、摄像头重连和进程退出等场景。模型升级前保留上一版模型与配置；升级后记录输入分辨率、推理帧率、内存占用和识别结果差异。若出现识别延迟增大，依次检查摄像头帧率、模型尺寸、CPU/NPU 占用、队列积压和网络发送频率，而不是盲目降低阈值。
