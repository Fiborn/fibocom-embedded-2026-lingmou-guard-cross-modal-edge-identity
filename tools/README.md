# 辅助工具

本目录存放模型转换、量化、调试和自动化辅助脚本。

## 当前内容

- `onnx_int8.py`：ONNX 模型 INT8 量化辅助脚本。
- `onnx2tflite-main/`：ONNX 转 TFLite 的第三方工具工程。

## 使用约定

- 工具输入模型与输出产物应放在临时目录或发布目录，不直接覆盖原始模型。
- 第三方工具保留其上游许可证和原始 README；升级时应记录来源与版本。

## 工具工作流

```text
原始模型 → ONNX 校验/简化 → 精度抽样验证 → TFLite 转换 → 量化 → 目标设备回归测试
```

`onnx2tflite-main/` 的运行依赖包括 ONNX、ONNX Runtime、ONNX Simplifier、TensorFlow、NumPy 与 OpenCV。转换前应备份原始模型；转换后至少验证输入输出形状、数值误差、推理耗时和目标设备兼容性。

## 输出管理

建议将转换结果置于单独的 `artifacts/` 或发布系统，并在文件旁记录源模型版本、命令、依赖版本、量化参数和校验和。不要把不明来源的模型直接部署到设备。

## 具体使用步骤

模型转换前，复制原始模型到受控的临时工作区，并记录文件哈希、输入尺寸和预处理规则。先使用 ONNX 工具检查模型是否可加载，必要时执行简化；随后调用 `onnx2tflite-main` 提供的转换能力生成 TFLite 文件。量化时必须明确使用的代表性数据范围与精度目标，避免因不匹配的数据导致识别性能明显下降。转换命令、依赖版本和输出文件名称应写入操作记录，便于复现。

转换完成后不能只检查文件是否生成，还应在 PC 和目标设备分别执行少量样本推理，比较输出维度、数值范围、推理耗时和内存占用。若结果异常，按原始模型、简化模型、浮点 TFLite、量化 TFLite 的顺序定位问题，并保留每一步的输出以便回滚。第三方工具升级前应在隔离环境验证，确认其许可证、Python/TensorFlow 兼容性和转换结果均符合项目要求，再更新正式工具链。
